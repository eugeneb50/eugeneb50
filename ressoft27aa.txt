### ZeroClaw Labs — Open-Source Contributor, Agentic AI Gateway
*github.com/zeroclaw-labs/zeroclaw · Rust agentic AI gateway, 32.8k stars · 2026 – Present*

- **PR #7946 — context-window meter (MERGED Jul 6, 2026; 39 commits).** Made
  `context_window` the single source of truth on `ModelProviderConfig` with
  `fetch_context_window()` across 9 providers (OpenRouter plus 8 OpenAI-compatible); added
  a `doctor update-context-windows` command and a gateway refresh endpoint; shipped the
  gateway WebSocket done frame, the web ContextBar, a per-turn CLI context summary, and the
  zerocode CtxBar widget. Cleared review from four maintainers covering Fluent i18n across
  5 locales, credential forwarding, and exact-alias write-back.
- **PR #8966 — serving-provider usage identity (MERGED Sep 18, 2026; 94 commits).** Made
  `TurnEvent::Usage` carry the live serving identity (provider, model, accepted flag) so
  usage, cost, and context-meter attribution follow the provider that actually served the
  call across fallback chains and in-turn model switches. Included a per-attempt
  `usage_by_provider` ledger in the gateway done frame, accepted/rejected separation in a
  dedicated `UsageFold`, alignment of the runtime cost pipeline with upstream pricing
  (`ModelRates`, `UnpricedUsage` provenance), durable ACP/RPC usage snapshots, a deliberate
  single-candidate stream-to-non-stream recovery policy with every settled billable attempt
  projected as a usage event, and separation of trim budget from display ceiling across
  gateway, RPC, zerocode, and web. Also fixed a pre-output stream-failure fallback bug
  (#10736).
- **PR #8337 — herdr agent reporting integration (CLOSED, superseded by #10269; 52 commits).**
  Designed and shipped an observer reporting agent lifecycle (idle, working, blocked,
  released) to persistent terminal sessions over JSON-RPC on Unix domain sockets, and
  iterated through four rounds of maintainer review — isolating I/O onto a bounded
  fire-and-forget thread so an unresponsive socket could not hang the agent loop, replacing
  a dead config section with environment-driven discovery, gating installation to interactive
  CLI scope, and reserving the terminal queue with stale-snapshot suppression and ordered
  shutdown drain. Superseded upstream; the superseding maintainer credited this work's
  lifecycle and delivery requirements as the basis for the canonical vendor-neutral
  `hooks.lifecycle_commands` boundary. Coordinating with the herdr maintainer on a
  standardized agent-integration adapter (herdrdev/herdr#811).

### herdr-mcp — Author
*github.com/eugeneb50/herdr-mcp · Rust Model Context Protocol server · 2026 – Present*

- **Built a 51-tool MCP server in Rust** across 10 tool groups, exposing a terminal-native
  agent multiplexer as callable tools, and shipped an **Axum HTTP bridge with a single-file
  React playground** so tools can be run, recipes chained, and results inspected with no dev
  server.
- **Plugs into Claude Desktop, Cursor, Claude Code, Continue, and OpenCode** over stdin and
  stdout JSON-RPC, so the same tools work in every host without a separate integration.
- **Tool surface:** discovery (7 — status, workspaces, tabs, panes, agents, and lookup),
  lifecycle (5 — create workspace or tab, split or close pane, start agent), read (2) and
  write (4) including run command, sync (3 — wait for output or status), agent-to-agent
  primitives (5 — spawn, message, read, wait, list with role and label resolution), plus
  message-trim (10), recipes (3), scheduler (4), folder-key (4), and clipboard (2).
- **Built the recipe engine and cron scheduler:** chains tool calls with
  `{{ stepId.result.path }}` variable interpolation, ships bundled recipe templates, and
  runs scheduled recipes on cron.
- **Built the message-trim pipeline** for agent-to-agent communication with two compressors
  — caveman (lossy, style) and pfc1 (lossless, Cherokee-syllabary phonetic) — with per-pane
  trim policies, per-folder PFC1 keys, and trim analytics and readiness checks.
- **Designed for a stable surface:** a Unix socket event subscriber tracks panes in real
  time for the live agent registry, and the server shells out to the herdr CLI via
  `tokio::process::Command` so there is no wire-protocol coupling to maintain. Every
  pane-targeting tool accepts either a pane ID or a human-readable label.
- **4-crate workspace, fully tested:** herdr-mcp-core, herdr-mcp-trim, herdr-mcp-server,
  herdr-mcp-cli. **299 tests passing, clippy clean**, plus a kitchen-sink ratatui TUI
  dashboard with mouse and keyboard navigation.
